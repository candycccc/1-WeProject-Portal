WeQuote CRM — Leads & Deals · Requirements

v1.0 draftCandy · Product/UX4 Jul 2026 Audience: Engineering (Robert's team)

Consolidates PRD v0.9 + all agreed amendments. Everything marked demo is clickable in this prototype — start at Leads.

1 Positioning2 Data model3 Automation 4 UI5 Permissions6 Zoho7 Reporting 8 Acceptance9 Roadmap10 Open questions11 Out of scope

1Positioning & problem

The CRM is used by WeQuote's dealer users (AV integrators, e.g. LCR Integrated Systems) to manage their own end customers' leads and deals. It is not an internal WeQuote-staff tool. Per Lee Roche: CRM is a dedicated section, separate from Quote & Sales.

Problem: WeQuote only tracks a sale once a Quote exists — no pre-quote prospects, and no object grouping option quotes of one opportunity. Result: pipeline value overstated (options double-count), win rate understated (each declined option counts as a loss), pre-quote opportunities live in email/memory.

Goal: add Lead + Deal in front of the Quote → Project chain, with deal state derived from quote events, plus pipeline UI and reporting.

Non-goals (Phase 1): custom objects, automation builder, email sync, standalone People object, weighted forecast, AI scoring/enrichment/summaries (Ask Ava / AI Overview in designs are Phase 2+ vision).

2Data model

2.1 Lead demo

FieldNotes
title"Lead Title" in the inbox. Derived from org/contact if not entered Q8
contact_name / job_titlePrimary contact person (required) + role
organisation_nameSeparate field from contact_name — never one free-text blob (§2.6)
phone / emailAt least one required
labelsCold / Warm / Hot (multi-select)
interestsProduct categories: Television, CCTV, Lighting, Home Cinema, Networking… (org-extendable)
site_addressPostcode search + manual; feeds Phase-3 map view
sourceOrg-configurable enum. Seed: word of mouth, contractor, designer, website, social, referral, exhibition, phone-in, other
owner / statusOwner defaults to creator. Status: open, converted, discarded (+ discard_reason)
est_valuePrioritisation aid only; never in pipeline reports; carried to the deal on convert
next_activityPhase 2 lead-level activities; until then show Created/Age
  • L1 — Lead creation creates the Customer. Same transaction, flagged prospect = true; default Customers list filters prospects out; flag clears on first deal/quote/project. demo
  • L2 — Duplicate check at lead creation. Fuzzy-match as you type; choosing a match attaches instead of creating a prospect.
  • L3 — Convert creates only the Deal (customer already linked); deal name = lead title, est value carried; lead becomes converted + read-only. demo
  • L4 — Discard needs a reason; discarded leads leave all lists/reports except a discard count.

2.2 Deal

One business opportunity for one customer; owns the pipeline stage; quotes attach to it. Fields: name, customer, owner, stage, estimated one-off + recurring values (P1 recurring = manual only; P2: suggested from history), value_locked, risk_notes, lost_reason, expected_close_date.

Deal↔Quote: nullable deal_id + scope_group_id on Quote (quotes without deals unchanged). Deal↔Project: deal_projects join table — schema lands in Phase 1; richer UI Phase 4.

2.3 Stages

Org-configurable; seed: Enquiry → Site survey → Design/spec → Proposal sent → Negotiation + fixed Won/Lost. Every transition recorded in deal_stage_events (from P1) for future time-in-stage reporting.

2.4 Scope groups demo

Named buckets of quotes in a deal. Same group = mutually exclusive options → group value = ★ primary quote (default: latest sent; override logged). Different groups are additive. Q9 draft-only group value rule.

2.5 Deal value

  • No quotes → manual estimates. Quotes exist → Σ primary values per group (deal_value_confirmed excludes likelihood=maybe).
  • Won → frozen at accepted amounts (change orders are project metrics, never sales). Lost → frozen for lost-value analysis.

2.6 Customer: type + structured naming

Customer gets explicit type: Organisation / Individual. Every entry point captures person and organisation as separate fields (lead form is the template). Duplicate check matches both. Legacy data untouched in P1 — cleanup via the Merge duplicates tool Phase 2.

3Automation rules must-have

Deal state derives from actions users already take while quoting — never manual board upkeep. Not shippable without all five. demo (convert → create quote → accept in the prototype)

  • A1 First sent quote → deal forward to "Proposal sent". Never auto-backwards.
  • A2 Quote accepted → group accepted, value frozen.
  • A3 Sibling options → system status Superseded: grey badge, excluded from Sent counts / win-loss / pipeline, no customer notifications, still reachable from deal + search.
  • A4 All groups resolved & ≥1 accepted → Won, value locked, skippable pre-filled Project prompt. All dropped → Lost (reason required).
  • A5 30 days no activity (org-configurable) → owner nudge via existing notifications; cards show days-since-activity, dimmed past threshold.
Quote eventDeal effect
In Progress / In Review / Passed ReviewNone (pre-send). Optional A0 [proposal]: first quote created → Design/spec
Sent (first on deal)A1 → Proposal sent
AcceptedA2 group accepted + A3 siblings superseded
CompleteNone — fulfilment status; deal was Won at acceptance
CancelledOut of group value. Cancelled ★primary → fall back to latest Sent in group (logged). Whole group cancelled → prompt owner to mark dropped, never automatic
Superseded (new)System-set only via A3

4UI

Navigation: CRM → Leads / Pipeline as a dedicated module (per Lee); Sales Overview/Targets stay under Quote & Sales. Global + Create includes Quote, Lead, Deal, Customer, Project, PO, Task. demo

  • 4.1 Leads inbox — Inbox/Archive toggle; columns Lead Title · Next Activity (red overdue) · Est. Value · Source · Created · Owner; row → drawer; Create Lead modal (split person/org fields, labels, interests, address, notes, CSV Import P3). demo
  • 4.2 Pipeline board — kanban, Won/Lost drop zones (deals never deleted), card shows value/owner/days-since-activity, column Σ, filters. Backwards drags Q3. demo
  • 4.3 Deal record — scope groups table (★ toggle, statuses), Create Quote from deal (pre-filled), contacts with per-deal roles, tasks, risk notes, activity log. demo
  • 4.4 Customer record — deals panel LEFT with stage-progress bars + + Deal button; right: Focus + History; Organisation/Individual + Prospect badges. Click-through: org name → customer page; person name → contact card popover ("Works at →"); Individual = straight to customer page. demo
  • 4.5 Existing screens — quote list shows deal link + Superseded badge; Sales Overview gains deal aggregates (§7).

5Permissions

Reuse existing roles. Default: all sales roles get "see all sales data" (whole team sees the pipeline — Pipedrive norm). Revoked users see own leads/deals only, board locked to self, Sales Overview shows own-only figures. No new primitives.

6Zoho coexistence

Zoho active → native CRM hidden or read-only Q4 (recommend read-only + banner). Never both writable. Migration tooling out of P1.

7Reporting (Phase 1)

Three numbers on Sales Overview: open pipeline by stage (one-off/recurring, confirmed vs incl-maybe) · win rate by deal · lost reasons. Restricted users: own-only. Customer-based reports/billing must use prospect = false.

8Acceptance scenarios

#Scenario
S1Options: group with A $420K (★) + B $360K → value $420K. B accepted → Won $360K, A superseded, 1 win 0 losses
S2Additive: AV $420K + Lighting $150K + Curtains $60K (maybe) → $630K, confirmed $570K; curtains dropped → Won $570K
S3B2B: recurring vs one-off separate; 4 groups; Won when all resolve, even signed at different times
S4Zero board interaction: quote sent → accepted yields Proposal sent → Won with correct locked value
S5Quotes with no linked deal behave exactly as today; deal-linked quotes reflect A3 display rules
S6Revoked permission → cannot see or aggregate colleagues' deals anywhere
S7Lead creates invisible prospect customer; convert creates only a deal; prospect clears on first deal

9Delivery roadmap

Phase 1 — Core pipeline (MVP): Lead inbox + source tagging + labels/interests · lead→prospect customer (L1/L2) · Deals kanban · convert flow · ⚠ quote-from-lead = convert → deal → Create Quote (optional one-click combo) · A1–A5 · scope groups + value engine · deal_projects schema · permissions · reporting · backfill = one deal per quote revision family (R1/R1.1/R2 → one deal/group, latest sent = ★).

Phase 2 — Automation & activities: ⚠ stage-triggered quote creation (configurable deal stage prompts a draft quote — replaces "lead moves into New Quote column"; there is no lead kanban) · quick actions · activity log lands here (meetings, site visits, calls, text/WhatsApp) + Next Activity column + Focus · suggested recurring from history · Merge duplicates tool.

Phase 3 — Content & data: attachments (drawings/PDF) → AWS bucket · CSV bulk import + Pipedrive/HubSpot path · map view for leads/sites (needs P1 site_address).

Phase 4 — Relationships & views: richer deal↔project linking UI · location / security-company / related-org associations · salesperson next-to-handle view · AI scoring/enrichment (Ask Ava).

Object model is locked: Lead (inbox, creates prospect customer) + Deal (kanban, owns stage/value) + scope groups. Nothing blocks Phase 1.

10Open questions — resolve before build

Q1 — Currency: org main currency only in P1? (Recommend yes.)
resolvedQ2 — Global + Create includes both Lead and Deal.
Q3 — Manual backwards drags past system-set stages? (Recommend allow + confirm + audit log; same policy as Q6.)
Q4 — Zoho-active accounts: hide or read-only? (Recommend read-only + banner.)
resolvedQ5 — Backfill = one deal per quote revision family.
Q6 — Accepted-quote reversal: group back to open + Won reopens to Negotiation with audit log, or disallowed? Must be explicit.
Q7 — Discarded lead's orphan prospect customer: auto-archive? (Recommend yes; restore on new lead.)
Q8 — Lead Title: explicit form field or always derived from org/contact?
Q9 — Scope group with only drafts: value rule (recommend 0 until first send).
Q10 — Lee's minutes predate L1 (lead-creates-customer) — confirm the change with Lee.

11Out of scope (explicit)

Custom objects · automation builder UI · email/calendar sync · AI enrichment/scoring/summaries · standalone People object · weighted forecast · Zoho migration tooling · mobile (Snagg) surface for deals.
